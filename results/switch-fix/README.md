# GPU/NPU切り替え不具合の修正（2026-10-12）

## 症状と調査

NPU workerが起動時の交互入力検証で停止し、両workerの準備完了を必要とするスライダーが無効になっていた。失敗記録は `../demo-20261012-145630-f4cb32/npu-validation.json` と同じディレクトリの `npu-alternating-mismatch.npz`。

再実行時にNPU中間出力の一部（28要素と56要素）が変化していた。枠の出力は一致していたが、中間出力の完全一致検証を通らなかった。既存のCPUスレッド数4固定だけでは再発を防げなかった。

NPU単独の5回の起動では、8入力のCPU/NPU比較と12回の交互入力検証がすべて成功した。生出力の300回の交互実行も成功。GPU/NPUの並行初期化を避ける構成へ変更した。デバイス・ランタイム内部で不一致が生じる詳しい原因は確定していない。

## 修正

- NPU検証完了→GPU初期化完了→カメラ/動画取得の順で開始する。HTTP画面は準備中も表示する。
- 準備中に終了しても、未開始のcapture threadにjoinして例外を起こさない。
- workerエラーがある場合、スライダー付近にも切り替え不可の理由を表示する。
- Chrome自動検証はカメラの640×480を許容し、映像受信を待ってから確認する。
- 数値基準0.05、モデル、量子化、完全一致検証は変更しない。

## 確認

[restart-regression.json](restart-regression.json) に5回連続の起動・Chrome操作を記録。各回でGPU/NPUのモデル検証に合格し、GPU→NPU→GPU→NPU→GPUと連続操作が成功。worker PIDを保ち、JavaScriptエラーなし。USBカメラの640×480映像を受信した。

CPUテストは8件成功。順次初期化が完了する前に次のworkerや入力取得を始めないことを回帰テストで確認した。最終稼働状態は [final-status.json](final-status.json)。物理カメラ切断の確認は行っていない。
